# МЭКОМ — онлайн-игра и локальный симулятор

Онлайн-режим: регистрация по логину и паролю, комнаты с владельцами, игра владельца
своей фирмой, приватные отчёты и общий отраслевой отчёт. Администратор видит готовность,
но не чужие решения. Принудительный расчёт требует отдельного подтверждения.
Аккаунты и онлайн-игры хранятся в серверной SQLite. Восстановления пароля нет.

**Публикация на Amvera:** [DEPLOY-AMVERA.md](DEPLOY-AMVERA.md).
Для готового архива: `npm run package:amvera` → `releases/mecom-amvera.zip`.
Требуется Node.js 24+; один экземпляр сервера и постоянное хранилище `/data`.

## Локальный режим ведущего

Приложение для ведущего экономической деловой игры МЭКОМ. Ведущий заводит лигу,
каждый период вводит по 5 решений на фирму, жмёт «Рассчитать» и получает
приватный отчёт по каждой фирме плюс один публичный отраслевой — их он рассылает
игрокам текстом или картинкой.

В локальном режиме всё считается в браузере, сервер и авторизация не нужны. Состояние живёт в
localStorage и переживает перезагрузку страницы; для бэкапа и переноса на другое
устройство есть экспорт/импорт JSON.

📖 **Полная документация — [DOCS.md](DOCS.md)**: все формулы движка, справочник
конфигурации, модель данных, обоснование спорных решений, покрытие тестами.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Для онлайн-режима сначала выполните `npm run build`, затем `npm run server`
(по умолчанию `http://127.0.0.1:8787`). Для разработки интерфейса запустите
`npm run dev` параллельно с сервером. Локальный режим открывается через кнопку
«Локальный режим», его данные остаются в браузере.

Прочие команды:

| Команда | Что делает |
|---|---|
| `npm test` | юнит-тесты движка и отчётов |
| `npm run typecheck` | проверка типов |
| `npm run build` | продакшен-сборка в `dist/` |
| `npm run smoke` | прогон партии в реальном браузере (нужен поднятый `npm run dev`) |

## Как устроен код

```
src/engine/    чистые функции расчёта, ноль зависимостей от UI
src/report/    рендер моноширинных отчётов в текст
src/state/     хранение лиг, localStorage, экспорт/импорт
src/ui/        экраны ведущего
```

Единственная точка входа движка:

```ts
computePeriod({ periodIndex, config, macro, firms, opening, decisions, previousIndustry })
```

Порядок фаз внутри — по ТЗ: спрос → себестоимость → продажи → инвестиции → P&L →
кэш-флоу → баланс → РИФ и агрегаты. Инвестиции считаются чуть раньше своего места
в списке, потому что формула себестоимости версии Б требует мощность следующего
периода; на модель это не влияет.

## Настраиваемость

Источники восстанавливают оригинальный движок по косвенным данным и местами
противоречат друг другу. Ни один спорный выбор не захардкожен — всё переключается
в настройках лиги:

| Развилка | Дефолт | Альтернатива |
|---|---|---|
| Формула себестоимости | версия Б (линейная) | версия А (U-образная) |
| База в версии Б | мощность текущего периода | стартовая мощность |
| Излишек заказов | пропорционально после штрафа | пересчёт по весам |
| Банковский процент | по траншам | плоская ставка |
| Банкротство | внешнее управление | заморозка / только метка |
| Гашение займа | не гасится | гасится избыток входящего кэша сверх затрат периода (`sweep`); может увести заём в минус — тогда это депозит под `depositRate` |

Там же лежат все «магические числа» — стоимость станка, срок службы, веса
70/15/15, степени 3/1.5, порог маркетинга 16 800, потолок цены и прочее. В
источниках прямо сказано, что часть из них — параметры конкретной партии, а не
константы движка.

## Что проверено на реальных данных

Движок сверен с настоящим отчётом фирмы «RLC» за 2-й период (единственный
доступный набор реальных входов и выходов). Тест `rlc-period2.test.ts`
воспроизводит все строки отчёта в пределах ±3 $:

- амортизация, СЕБЕСТ, валовый доход, прибыль до налога, налог 32%, чистая прибыль;
- банковский процент по траншам: 60 000 × (20%+1%)/4 + 20 002 × 80%/4 = 7 150;
- наличные на конец периода 51 096 и капвложения 48 153;
- баланс: актив = пассив + капитал = 99 249;
- загрузка мощности 698/873 = 80.0% (а не 698/1203).

Три вещи пришлось вывести самостоятельно — источники их не дают или дают
противоречиво. Каждая обоснована комментарием в коде:

1. **Множитель маркетинга** (`demand.ts`): корень охватывает обе ветки формулы,
   иначе на пороге 16 800 возникает разрыв в 130 раз. Даёт 2861 заказ при
   калибровочном ориентире 2860.
2. **Кэш-флоу** (`cashflow.ts`): официальная запись не учитывает входящий остаток
   наличных и формально запрещает иметь одновременно кэш и долг, чего в реальном
   отчёте нет. Револьверная форма сходится с отчётом до доллара и делает тождество
   баланса верным по построению.
3. **Остаток в амортфонде** (`capex.ts`): накапливается между периодами — иначе
   капвложения в отчёте не сходятся на 33 $.

Формулу себестоимости проверить не на чем: в источнике нет данных за период 0 той
же фирмы. Поэтому обе версии доступны и легко сравнимы.

## Ограничения

Нет восстановления пароля, подтверждения почты и горизонтального масштабирования.
Старые локальные игры и серверный JSON не мигрируются в онлайн-аккаунты автоматически.
Резервные копии SQLite на том же диске нужно дополнительно скачивать вне сервера.
