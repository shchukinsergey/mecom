# МЭКОМ: публикация на Amvera

## Что подготовлено

Один контейнер содержит сайт и сервер. Отдельная платная база не нужна: SQLite хранит аккаунты, сессии, комнаты, решения и результаты. Экономический движок сохранён. Требуется Node.js 24 или новее с `node:sqlite`; готовый Docker-образ использует Node.js 24.

Для первого запуска рассчитано на один экземпляр приложения, тариф с 500 МБ RAM. Горизонтальное масштабирование этого варианта не предусмотрено. Потребление памяти нужно проверить после публикации: локальные замеры не гарантируют результат в облаке.

## Самый простой путь — готовая сборка

На компьютере в папке проекта:

```sh
npm ci
npm run package:amvera
```

Получится `releases/mecom-amvera.zip`. В нём только `dist/`, `dist-server/`, Dockerfile, конфигурация и эта инструкция. Аккаунты, базы, пароли, `.env` и локальные игры в архив не попадают. Dockerfile из архива **не собирает TypeScript на сервере**: он запускает готовую сборку.

1. Создайте приложение в Amvera, выберите Docker и тариф «Начальный».
2. Распакуйте архив на своём компьютере. Загрузите его **содержимое** в папку **Code** приложения с сохранением структуры каталогов. В корне должны лежать `Dockerfile` и `amvera.yml`, рядом — папки `dist` и `dist-server`. Не загружайте всё одной лишней вложенной папкой и не кладите код в Data.
3. Во вкладке переменных окружения задайте:

   | Переменная | Значение |
   |---|---|
   | `NODE_ENV` | `production` |
   | `PORT` | `8080` |
   | `MECOM_DATA_DIR` | `/data` |
   | `NODE_OPTIONS` | `--max-old-space-size=256` |
   | `MECOM_PUBLIC_ORIGIN` | полный HTTPS-адрес вашего приложения, без пути и завершающего `/` |

   Пример формата последней переменной: `https://ваш-адрес-приложения`. Используйте фактический адрес из настроек Amvera. Он нужен для защиты от сторонних запросов; значение должно совпадать с адресом, по которому друзья открывают сайт.
4. Убедитесь, что постоянное хранилище смонтировано в `/data`, порт контейнера — **8080**. Это задано в `amvera.yml`.
5. Запустите сборку/развёртывание, подключите предоставленный Amvera адрес и HTTPS в настройках сети.
6. Откройте сайт, зарегистрируйтесь, создайте комнату и отправьте ссылку друзьям. Покупать свой домен не обязательно.

Ключ администратора не нужен: создатель каждой комнаты автоматически становится её администратором. Пароль нигде в переменных Amvera вводить не требуется.

### Через Git вместо ручной загрузки

В корне репозитория также есть исходный многоэтапный `Dockerfile`. Он устанавливает зависимости и выполняет сборку внутри Docker. Можно отправить исходники через Git в Amvera вместо готового архива. Для маленького тарифа удобнее готовая локальная сборка.

## Правила игры

- Логин: 3–32 латинские буквы, цифры, `_` или `-`, без различия регистра. Пароль: 8–128 символов (ограничен также размер в UTF-8).
- Нет почты, подтверждения и восстановления пароля. Предупредите друзей: забытый пароль восстановить средствами сайта нельзя.
- Открытые комнаты в лобби видны в общем списке. Комнаты «По ссылке» не попадают в него; доступ возможен по ссылке после входа. Ссылка не даёт административных прав.
- В каждой комнате у аккаунта не больше одной фирмы. Создатель может играть сам либо только вести игру. В разных комнатах роли независимы.
- Для старта нужно хотя бы две фирмы; после старта состав фиксируется.
- Администратор видит готовность, общий отраслевой отчёт и только свои частные данные, если играет. Чужих решений и частных отчётов сервер ему не отправляет.
- Нормальный расчёт требует готовности всех. Принудительный открывает отдельное подтверждение: использовать сохранённый черновик неготовой фирмы, а при его отсутствии — прошлое решение. Если решение недопустимо в текущем периоде, расчёт блокируется. Значения автоматически не придумываются.
- Проверка номера периода защищает от повторного расчёта после двойного клика или устаревшей вкладки.
- Локальный режим доступен отдельно, сохраняется в браузере как раньше. Старые локальные лиги не становятся общими онлайн-комнатами автоматически. Старый серверный JSON и вход по токенам не мигрируются в аккаунты.

## Данные и резервные копии

Рабочая база: `/data/mecom.sqlite`. Рядом SQLite может создавать `-wal` и `-shm` — это нормальные служебные файлы.

Приложение делает согласованные SQLite-копии при старте и раз в сутки в `/data/backups/`, оставляя семь последних датированных копий. Это **локальные копии на том же хранилище**, а не защита от удаления приложения или потери всего диска. Иногда скачивайте последнюю копию из Data на свой компьютер. В копиях содержатся хеши паролей и сессии: не публикуйте их и не кладите в Code.

Для восстановления:

1. Остановите приложение.
2. Скачайте текущую базу и служебные файлы как страховочную копию.
3. Замените `/data/mecom.sqlite` выбранной согласованной резервной копией, переименовав её в `mecom.sqlite`. После остановки удалите старые `mecom.sqlite-wal` и `mecom.sqlite-shm`, если они остались.
4. Запустите приложение и проверьте вход и комнаты.

Не копируйте только рабочий `mecom.sqlite` во время игры: часть последних изменений может находиться в WAL. Используйте готовые файлы из backups или остановите приложение.

## Локальная проверка перед загрузкой

```sh
npm test
npm run typecheck
npm run build
npm run server
```

Полный браузерный прогон аккаунтов и комнат: `npm run smoke:rooms` после сборки.
Он запускает отдельный сервер с временной базой и системный Microsoft Edge;
реальные сохранения не меняет. При необходимости задайте `MECOM_BROWSER_CHANNEL=chrome`.

Без `NODE_ENV=production` сервер слушает только `127.0.0.1:8787`, cookie подходит для локального HTTP. В production сервер слушает `0.0.0.0`, cookie требует HTTPS. Не отключайте production для публикации.

Для разработки интерфейса параллельно запустите `npm run dev`: Vite проксирует `/api` на `127.0.0.1:8787`.

Старый запуск через токены оставлен как явно включаемый локальный режим `MECOM_MODE=legacy`; публичный account-сервер старые API не обслуживает.

## После первого развёртывания

Проверьте два независимых аккаунта: регистрацию, ссылку комнаты, готовность игроков, обычный и принудительный расчёт. Перезапустите приложение и убедитесь, что аккаунты и результаты остались. Только после этой проверки приглашайте всю компанию.

Документация провайдера:
- Docker: https://docs.amvera.ru/applications/configuration/docker.html
- Постоянное хранилище: https://docs.amvera.ru/applications/storage.html
- Сеть и домены: https://docs.amvera.ru/applications/configuration/network.html

Развёртывание и проверка публичного адреса требуют доступа к вашему аккаунту Amvera; локальная сборка не означает, что сайт уже опубликован.
