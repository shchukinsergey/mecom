# Telegram-уведомления

Интеграция работает в серверном онлайн-режиме с аккаунтами и SQLite.
Локальные браузерные лиги и режим `MECOM_MODE=legacy` к боту не подключаются.

## Личный Telegram и вход

Подключение необязательно: вход по логину/паролю и локальный режим сохраняются.
Существующему пользователю нужно сначала войти обычным способом, затем в разделе
«Уведомления» нажать «Подключить Telegram». На странице входа кнопка «Войти через
Telegram» входит в связанный аккаунт; если связи ещё нет, создаёт новый аккаунт.
Аккаунты автоматически по имени или username не объединяются.

Сайт выдаёт команду `/login код`. Откройте бота и отправьте команду в личный чат,
затем вернитесь на сайт: завершение проверяется автоматически. Код действует
5 минут, одноразовый; не отправляйте коды с чужих страниц. Код для бота и секрет
завершения в исходном браузере различаются. Дополнительные ключи Login Widget
не нужны: вход работает через существующий webhook бота.

Один Telegram связан с одним игровым аккаунтом. Игрок получает личные сообщения
о следующих периодах и завершении своих игр; за час до дедлайна — напоминание,
если он ещё не отправил решение. Блокировка бота отключает личную доставку;
повторное подключение её восстанавливает. Подключение в середине периода
не отправляет задним числом сообщение о его начале.

Для аккаунта с паролем Telegram можно отключить в настройках. Для созданного
через Telegram аккаунта отключение запрещено, поскольку это единственный способ
входа. Установки пароля для такого аккаунта и восстановления доступа пока нет.

В групповых рейтингах и напоминаниях рядом с фирмами показываются упоминания
связанных участников. Используется Telegram ID, поэтому отсутствие username
не мешает формированию ссылки; Telegram определяет фактическую доставку упоминания.
Без привязки отображается только фирма. Личные отчёты и решения не публикуются.

## Настройка сервера

1. Создайте бота через [@BotFather](https://t.me/BotFather). Разрешите добавление в группы.
2. В переменных окружения Amvera задайте:

   | Переменная | Значение |
   |---|---|
   | `MECOM_PUBLIC_ORIGIN` | Публичный HTTPS-адрес МЭКОМ без пути |
   | `MECOM_TELEGRAM_BOT_TOKEN` | Токен BotFather, хранится только на сервере |
   | `MECOM_TELEGRAM_BOT_USERNAME` | Имя бота без `@` |
   | `MECOM_TELEGRAM_WEBHOOK_SECRET` | Случайная строка из 16–256 латинских букв, цифр, `_` и `-` |

   Секрет можно создать командой `openssl rand -hex 32`. Токен и секрет нельзя коммитить.
3. Соберите и перезапустите приложение. При запуске сервер регистрирует webhook
   `/api/telegram/webhook` с секретным заголовком и команды `/connect`, `/help`.
4. При ошибке регистрации в журнале появится `Telegram webhook setup failed`.
   Проверьте переменные и доступность HTTPS-адреса, затем перезапустите сервер.

Без переменных Telegram игра работает как прежде; раздел уведомлений сообщает,
что бот не настроен. Если задана часть переменных бота, запуск завершится ошибкой
конфигурации. Файл `.env.example` служит образцом: автоматического чтения `.env` нет.
Используйте одного бота для одного окружения: регистрация webhook заменяет предыдущий адрес.

Отдельные Redis, cron или процессы не нужны. Как и для основного приложения,
нужен один экземпляр сервера с постоянным хранилищем SQLite в `/data`.

## Подключение чата

1. Авторизуйтесь в МЭКОМ и откройте «Telegram · уведомления».
2. Добавьте бота по ссылке в групповой чат; разрешите ему отправлять сообщения.
   Для обычных уведомлений права администратора самому боту не нужны.
3. Создайте код подключения и отправьте предложенную команду `/connect@имя_бота код`
   в чат. Отправитель должен быть администратором чата; анонимные команды не принимаются.
4. Чат появится в разделе Telegram автоматически, в течение 10 секунд.
5. Отметьте собственные игры и нажмите «Сохранить выбор игр».

Код одноразовый, действует 10 минут, новый код заменяет предыдущий.
Он даёт право связать чат с вашим аккаунтом: отправляйте его самостоятельно.
При сохранении списка игр повторно проверяется, что подключивший чат Telegram-пользователь
остаётся его администратором. Подключить чужую игру нельзя.
Несколько владельцев могут подключить свои игры к одному чату с помощью своих кодов;
каждый управляет только собственными играми.

В одном чате можно выбрать несколько игр; у одной игры может быть несколько чатов.
Для отключения снимите отметки и сохраните: ожидающие сообщения этих игр удалятся.
Если бот удалён, заблокирован или лишён возможности писать, чат отмечается неактивным.
После восстановления прав подключите его новым кодом. При преобразовании группы
в супергруппу также нужно подключить чат заново.

## Сообщения

- При запуске игры — номер первого периода и дедлайн, без рейтинга калибровочного периода 0.
- При новом периоде — номер, дедлайн и таблица «Фирма — РИФ» за предыдущий период.
  Сортировка по убыванию полного значения РИФ; при равенстве — по названию.
  Отображение с одним десятичным знаком. В рейтинге все фирмы из рассчитанного результата.
- После последнего периода — «Игра завершена» и итоговый рейтинг.
- В стандартном режиме — одно напоминание за час до дедлайна со списком
  действующих команд, которые не нажали «Отправить». Черновик не считается сдачей.
  Компьютерная фирма и исключённые банкроты не попадают в список.
  В быстром режиме на 7 минут и без ограничения времени напоминания нет.
- При подключении к активной игре — текущий период с последним рейтингом;
  к завершённой — итоговый рейтинг. В лобби — подтверждение подключения игры.

Время показывается по Москве. Каждое игровое сообщение содержит кнопку «Открыть игру»;
для доступа действуют обычные правила входа МЭКОМ. Бот публикует только названия фирм
и публичный РИФ, без значений решений или личных отчётов.

## Доставка и восстановление

Событие смены периода сохраняется в одной транзакции с состоянием игры.
Очередь, связи и отметки отправки находятся в той же SQLite и входят в её резервные копии.
Обработчик запускается при старте и каждые 30 секунд: точность напоминания — около 30 секунд
плюс время запроса к Telegram. Дедлайны берутся из существующей логики игры.

При временной ошибке запрос повторяется с растущей задержкой; для Telegram 429 учитывается
`retry_after`. Перед каждой попыткой напоминания список несдавших читается заново.
Просроченные напоминания и сообщения старых периодов пропускаются. Если сервер
восстановился внутри последнего часа, сообщение показывает фактические оставшиеся минуты.
Если все сдали решения, напоминание не отправляется.

Удаление подписки отменяет ожидающие сообщения; запрос, уже отправленный Telegram,
отменить нельзя. После неоднозначного сетевого сбоя или сбоя между отправкой и отметкой
в SQLite возможен редкий дубль: Bot API не предоставляет ключ однократной отправки.
Восстановление старой резервной копии также может повторить сообщения, отправленные после её создания.

## Проверка

`npm test` проверяет доступ, одноразовые коды, события всех способов расчёта,
рейтинг, напоминания, повторные попытки, завершение игры и отключение подписок
через подменённый Telegram API. `npm run build` проверяет типы клиента/сервера и сборку.
`npm run smoke:telegram` после сборки проверяет настройки в системном Chrome
(путь можно задать через `CHROME_PATH`); Telegram API подменяется, бот не нужен.
Для проверки реальной доставки нужны настроенный бот, публичный HTTPS-сервер и тестовый чат.

Документация API: [setWebhook](https://core.telegram.org/bots/api#setwebhook),
[sendMessage](https://core.telegram.org/bots/api#sendmessage),
[getChatAdministrators](https://core.telegram.org/bots/api#getchatadministrators).
